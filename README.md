# ЛР 3. Каталог авиационных деталей

Пакет `src` содержит модель авиационной детали, каталог с поиском и сохранение в JSON. Требуется Python 3.12+. Для работы с каталогом используются импорт классов и вызовы функций.

## Сущность и инварианты

`Detail` — неизменяемый `dataclass(frozen=True)`. Проверки выполняются в `__post_init__`, то есть при создании, до добавления объекта в каталог.

| Поле | Тип и ограничение |
|---|---|
| `identifier` | Строка, не пустая после `strip()`. Уникальность проверяется каталогом |
| `name` | Название: непустая строка |
| `category` | Категория: непустая строка |
| `date` | Календарная дата `datetime.date` без времени; `datetime.datetime` запрещён |
| `mass` | Положительное конечное число `int` или `float`; `bool` запрещён |
| `material` | Материал: непустая строка |

`mass` и `material` — два дополнительных поля предметного варианта. В примерах масса задана в килограммах; автоматического пересчёта единиц нет. Будущие даты не запрещаются.

Проверка `strip()` не изменяет исходные строки: пробелы по краям сохраняются. Идентификаторы сравниваются точно, с учётом регистра и пробелов. Проверки значения идентификатора выполняет сущность, проверку его уникальности среди деталей — каталог. Недопустимые поля вызывают `InvalidDetailError`, повторный ID при добавлении — `DuplicateIdError`. После создания менять поля детали нельзя; попытка присваивания вызывает `dataclasses.FrozenInstanceError`.

## Каталог и поиск

`Catalog` хранит словарь «ID → объект Detail». Поиск по ID использует обращение к словарю без перебора всей коллекции.

| Операция | Поведение |
|---|---|
| `add(item)` | Добавляет деталь, возвращает `None`; занятый ID вызывает `DuplicateIdError` без перезаписи прежней детали |
| `get(item_id)` | Возвращает объект `Detail`; отсутствующий ID вызывает `ItemNotFoundError` |
| `remove(item_id)` | Удаляет деталь, возвращает `None`; отсутствующий ID вызывает `ItemNotFoundError` |
| `find_by_category(category)` | Возвращает новый список деталей с полным совпадением категории без учёта регистра |
| `find_by_name(query)` | Возвращает новый список деталей, название которых содержит подстроку без учёта регистра |
| `len(catalog)` | Количество деталей |
| `item_id in catalog` | Проверка наличия строкового ID, а не объекта детали |
| `iter(catalog)` | Новый итератор по объектам деталей |

Для сравнения названий и категорий используется `casefold()`. Запрос «ШЕСТЕР» находит «Шестерня привода». Категория «Мех» не совпадает с «Механика». Пустой запрос названия находит все детали. Отсутствие совпадений даёт пустой список.

**Порядок фиксирован: порядок добавления.** Перебор и результаты поиска следуют этому порядку; два обхода неизменённого каталога дают одинаковую последовательность. Удаление сохраняет относительный порядок остальных деталей. Повторное добавление удалённого ID помещает его в конец.

Методы поиска каждый раз создают отдельный список. Его очистка или изменение состава не меняет каталог. Сами детали не копируются, но их поля неизменяемы. Изменения состава каталога выполняются через методы `Catalog`; прямое редактирование внутреннего словаря `items` обходит проверки и не входит в контракт использования.

### Пример использования

Запустите `python` из корня проекта и выполните:

```python
from datetime import date

from src.catalog import Catalog
from src.detail import Detail
from src.storage import load_catalog, load_into_catalog, save_catalog

catalog = Catalog()
gear = Detail(
    identifier="ART-0042",
    name="Шестерня привода",
    category="Механика",
    date=date(2026, 11, 12),
    mass=1.45,
    material="Сталь",
)
catalog.add(gear)

print(catalog.get("ART-0042").name)
print(len(catalog))
print("ART-0042" in catalog)
print(catalog.find_by_name("ШЕСТЕР") == [gear])

save_catalog(catalog, "catalog.json")
restored = load_catalog("catalog.json")
print(list(restored) == [gear])

current = Catalog()
current.add(Detail(
    "ART-0043", "Болт крепёжный", "Механика",
    date(2026, 11, 13), 0.05, "Сталь",
))
load_into_catalog(current, "catalog.json")
print([item.identifier for item in current])
```

## JSON и атомарная загрузка

Файл записывается в UTF-8 с читаемым русским текстом и отступом 2. В корне обязательны целочисленный `format_version` и список `items`; `bool` вместо версии запрещён. Поддерживается версия 1. Пример документа:

```json
{
  "format_version": 1,
  "items": [
    {
      "identifier": "ART-0042",
      "name": "Шестерня привода",
      "date": "2026-11-12",
      "mass": 1.45,
      "category": "Механика",
      "material": "Сталь"
    }
  ]
}
```

Все шесть полей каждой записи обязательны. При сохранении дата преобразуется через `isoformat()`, при загрузке восстанавливается через `date.fromisoformat()`. Повторное создание `Detail` проверяет инварианты, добавление через `add` проверяет ID. Дополнительные ключи документа и записи не используются. Пустой каталог сохраняется как `items: []`.

| Функция | Принимает | Результат |
|---|---|---|
| `save_catalog(catalog, path)` | Каталог и путь | Записывает весь каталог, возвращает `None`; существующий файл перезаписывается, исходные объекты не меняются |
| `load_catalog(path)` | Путь | Возвращает новый проверенный каталог; существующие каталоги не меняет |
| `load_into_catalog(catalog, path)` | Существующий каталог и путь | Дополняет переданный каталог, возвращает `None` |

**Загрузка в существующий каталог сохраняет старые детали.** Сначала полностью читается файл, затем во временном каталоге собираются существующие и новые детали. Только после успешной проверки всех записей и ID подготовленное состояние применяется к исходному каталогу. Старые детали идут первыми, загруженные добавляются в порядке записей файла. Загрузка пустого каталога ничего не удаляет.

Ошибка даже во второй или последующей записи не добавляет корректные предыдущие записи частично. При конфликте загружаемого ID с существующим отменяется всё дополнение: исходные состав, порядок и объекты сохраняются. Конфликт не пропускается и не перезаписывает старую деталь.

`replace_with(other)` — вспомогательная операция полной замены словаря его копией. `load_into_catalog` передаёт ей уже объединённое содержимое, поэтому при загрузке старые детали сохраняются. Словари получателя и источника независимы.

## Исключения

Все предметные ошибки наследуются от `CatalogError`.

| Исключение | Причина |
|---|---|
| `InvalidDetailError` | Недопустимые поля при прямом создании `Detail` |
| `DuplicateIdError` | Повторный ID при `add` или конфликт файла с существующим каталогом при дополнении |
| `ItemNotFoundError` | Получение или удаление отсутствующего ID |
| `UnsupportedFormatVersionError` | Целочисленная версия JSON не поддерживается |
| `CorruptedFileError` | Повреждённый UTF-8, синтаксически повреждённый JSON, неправильная структура, отсутствующие поля, недопустимая запись или дубликат внутри файла |

Дубликаты **внутри файла** считаются повреждением документа и превращаются в `CorruptedFileError`. Конфликт корректного файла с **уже существующим каталогом** вызывает `DuplicateIdError`. Ошибки восстановления записи сохраняют исходную причину через цепочку исключений.

Ошибки открытия и записи файлов, например `FileNotFoundError` и `PermissionError`, остаются встроенными исключениями операционной системы.

## Сложность

| Операция | Время | Дополнительная память |
|---|---|---|
| `get`, проверка ID через `in` | В среднем O(1) | O(1) |
| `add`, `remove` | В среднем O(1), добавление — амортизированно | O(1) на операцию без учёта хранения новой записи |
| `len` | O(1) | O(1) |
| Создание итератора / полный обход | O(1) / O(n) | O(1) |
| Поиск категории или названия | O(n) проверок объектов плюс обработка строк | O(k) для k совпадений |
| Сохранение / загрузка нового каталога | O(n) записей плюс сериализация строк | O(n) |
| Дополнение существующего каталога | В среднем O(n + m) для n старых и m новых записей | O(n + m) |

Оценки ID-операций указаны для словаря. У поисков дополнительно учитывается работа `casefold()` и проверки подстроки; время зависит от длины текста. Отдельный индекс по категории не реализован, поэтому поиск категории перебирает каталог. Сам каталог занимает O(n) памяти.

## Тестирование

```powershell
python -m pytest -q
python -m ruff check src tests
python -m ruff format --check src tests
```

На контрольном запуске с CPython 3.14.7 выполнены 50 тестовых случаев. Ruff lint проверяется отдельно от форматирования; успешный `ruff check` не означает, что `ruff format --check` не найдёт замечаний.

- `tests/test_detail.py`: корректная сущность, недопустимые строки и даты, отказ для `datetime`, нулевая и отрицательная масса, неверные типы, `bool`, NaN и бесконечность.
- `tests/test_catalog.py`: добавление, получение, удаление и ошибки, дубликаты, независимость каталогов, повторный обход и его порядок, `len` и `in`, поиск подстроки с разным регистром, пустые результаты и независимость списков поиска.
- `tests/test_storage.py`: все поля JSON, сохранность исходных объектов, пустой каталог, round trip, восстановление типа даты, большая целая масса без потери значения, повреждённые JSON и UTF-8, неизвестная версия, неверная масса, дубликаты внутри файла, дополнение существующего каталога, ошибка во второй записи, конфликт ID и копирование словаря.

Файлы тестов создаются во временных каталогах через `tmp_path`. Проверка ошибки во второй записи подтверждает отсутствие частичного изменения, а отдельный тест конфликта ID проверяет атомарность объединения после успешного чтения файла.

## Принятые ограничения

- Загрузка JSON целиком и временное объединение выполняются в памяти. Атомарность относится к ошибкам загрузки, а не к одновременной работе нескольких потоков или атомарной записи файла.
- Реализована обязательная часть. Дополнительные задания не заявляются; неизменяемость `Detail` сама по себе не является read-only view каталога.
